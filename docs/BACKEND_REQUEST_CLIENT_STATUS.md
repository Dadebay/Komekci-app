# Backend: мастер меняет статус клиента (Новый / Постоянный / VIP)

Статус: **запрошено, не реализовано.** Flutter-экран для мастера готов к подключению после этого изменения.

## Зачем

В списке клиентов мастера (экран «Müşderiler») есть три статуса и счётчики по ним:

| В приложении | Значение `status` (желаемое) |
| --- | --- |
| Täze / Новые | `new` |
| Hemişelik / Постоянные | `regular` |
| VIP | `vip` |

Сейчас `GET /me/clients` отдаёт `status` как готовую строку, а изменить его нельзя: `PATCH /me/clients/{id}`
принимает только `private_note`. Мастер не может перевести клиента из «Новый» в «Постоянный» или «VIP».

## Что нужно сделать

### 1. Принимать `status` в `PATCH /me/clients/{id}`

Тот же эндпоинт, что и для заметки. Поле необязательное, можно отправлять отдельно или вместе с `private_note`.

```http
PATCH /api/me/clients/c12
Authorization: Bearer <токен мастера>
Content-Type: application/json

{ "status": "vip" }
```

- `{id}`: как в списке, `c12` (связь с аккаунтом) или `o4` (офлайн-клиент). Работает для обоих типов.
- `status`: одно из `new`, `regular`, `vip`.
- Можно отправить `{ "private_note": "…", "status": "regular" }` одним запросом.
- Повторная отправка того же значения не должна давать ошибку (идемпотентно).

Ответ `200`: обновлённый клиент в том же виде, что элемент `data` из `GET /me/clients`, чтобы приложение не
перезапрашивало список:

```json
{
  "data": {
    "id": "c12",
    "offline": false,
    "name": "Aydogdy",
    "nickname": "aydogdy_90",
    "phone": "+99361030911",
    "photo_url": null,
    "appointment": null,
    "last_visit": null,
    "visits": 0,
    "no_shows": 0,
    "spend": "0.00",
    "status": "vip"
  }
}
```

(Если проще оставить прежний ответ `{ "status": "ok" }`, приложение справится: оно перечитает клиента отдельно.
Но тогда в теле запроса и в ответе слово `status` значит разное, поэтому предпочтителен вариант выше.)

### 2. Ошибки

| HTTP | `error` | Когда |
| --- | --- | --- |
| 422 | `VALIDATION` | `status` не из списка `new` / `regular` / `vip` |
| 404 | `NOT_FOUND` | клиента нет или он принадлежит другому мастеру |
| 403 | `SUBSCRIPTION_SUSPENDED` | только если для остальных изменений клиентов так же (поведение как у соседних эндпоинтов) |

Клиент другого мастера нельзя изменить ни при каких условиях: проверять, что связь/офлайн-клиент принадлежит
текущему мастеру.

### 3. Статус хранится на стороне мастера

Статус нужен **для каждой пары мастер ↔ клиент отдельно**. Один и тот же человек может быть VIP у одного мастера
и «Новым» у другого. Не хранить его в профиле клиента.

### 4. Автоматический статус и ручной не должны спорить

Сейчас статус, судя по всему, считается автоматически (например, «Новый» до первого визита). Нужно решить и
зафиксировать правило. Предлагаемое:

- Пока мастер не менял статус вручную, работает автоматический расчёт, как сейчас.
- После ручного изменения хранится выбор мастера, и автоматика его **не перезаписывает** (иначе клиент,
  которого мастер сделал VIP, через день снова станет «Новым»).
- Если нужен сброс к автоматическому режиму, можно принять `"status": null`. Приложению это пока не нужно.

Если автоматических статусов нет вообще и всё считается на лету, достаточно хранить ручное значение и отдавать его,
а когда его нет, использовать нынешнюю логику.

### 5. Что не должно меняться

- Формат и порядок остальных полей в `GET /me/clients` и `GET /me/clients/{id}`.
- Значения `status` в списке должны быть теми же `new` / `regular` / `vip` (приложение сейчас разбирает строку
  мягко, но лучше отдавать ровно эти три значения). Если сейчас отдаются другие строки, пришлите список.
- Счётчики и фильтры в приложении считаются на клиенте по полю `status`, ничего дополнительного добавлять не нужно.

## Проверка (curl)

```bash
# перевести клиента в VIP
curl -X PATCH https://komekchi.brandsforlesstm.com/api/me/clients/c12 \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"status":"vip"}'

# в списке должен стать vip
curl https://komekchi.brandsforlesstm.com/api/me/clients -H "Authorization: Bearer $TOKEN"

# неверное значение: 422 VALIDATION
curl -X PATCH https://komekchi.brandsforlesstm.com/api/me/clients/c12 \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"status":"gold"}'
```

## Что сделает приложение после этого

На карточке клиента появится выбор статуса (Новый / Постоянный / VIP). Приложение отправит `PATCH` с полем
`status`, обновит клиента в списке и пересчитает счётчики. Ошибки покажет обычным сообщением.
